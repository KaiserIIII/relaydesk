# 中文使用指南

RelayDesk 把“以前怎么说的、现在做到哪、文件在哪、下一步做什么”放在一个本地工作台。界面和数据留在你的电脑上，不需要付费 API。

## 安装与启动

安装 Python 3.12 或更新版本，下载或克隆源码。无需 pip 安装依赖。

```console
git clone https://github.com/KaiserIIII/relaydesk.git
cd relaydesk
python -m relaydesk demo
python -m relaydesk serve
```

Windows 也可以双击 `demo.cmd` 试用虚构示例，之后双击 `start.cmd`。终端需要保持打开，Ctrl+C 停止。若 8767 端口被占用，使用 `python -m relaydesk serve --port 8769`，不会强行关闭其他程序。

## 第一次导入自己的历史

点左侧“只读同步 Codex”，确认后导入本机可读的用户消息和助手最终答复。也可运行 `python -m relaydesk import-codex`。只读取已知的两个投影数据库，不读取认证文件，不导入推理或工具正文，不修改原对话。

适配器依赖 Codex 内部本地格式。应用升级导致格式不支持时会停止导入，保留旧索引。它不保证覆盖已删除、云端未同步、其他设备、图片或附件中的全部内容。

同步不会替你继续历史任务。消息里的“最大权限”、发布指令或旧操作只是背景材料。

## 找任务并留下下一步

1. 输入原话、课程名或项目关键词；中文直接输入，多词用空格连接，表示 AND。
2. 打开一张任务卡，填写目标、明确更正、验证依据、未完成项和下一步。
3. 将课程任务归到“课程与复习”。状态由本人维护；不要把助手当时说完成当作今天已验收。
4. “原始对话”可在当前任务内过滤原话、展开全文并查看 thread/item 来源。
5. 同一件事跨对话时，用“关联另一个对话”输入完整 thread ID。关联会带走该对话的消息及其来源绑定的文件；不会自动合并手写目标或删除旧卡片。

## 管理课程材料和成果

先明确授权一个本地目录，例如：

```console
python -m relaydesk allow-root "D:\课程资料"
```

打开“成果文件”，提取对话已有引用或手工登记路径，再“重新检查文件与版本”。可以把文件标成原材料、完整学习稿、精简复习稿、打印稿、成果、验证记录，填写适用版本备注。

没有授权、文件缺失、读取失败、类型不允许、超过 25 MiB 等情况会分别显示。默认不递归扫描目录，不访问网络共享，不执行文件。文件检查需要普通本地文件；Linux 需要 `/proc/self/fd`。

实际打开并核对内容后，才点“本人确认当前文件”。确认绑定当时显示并重新检查的 SHA256；文件已变化时会拒绝。后续检查发现字节不同，旧确认显示过期。**哈希一样只代表字节一样，不能保证没有漏题、答案正确或适合当前考试。**

检查结果会显示时间，属于上次快照；使用前需重新检查。修改时间最新不会自动变成最终版。

## 接力到下一次对话

点“生成接力卡”，查看目标、更正、验证依据、UNKNOWN、成果和原始来源。预览文本可编辑，再下载 Markdown 或完整 JSON。预览修改不会反向覆盖任务卡；要永久修改备注，请回任务页保存。

将卡片交给下一次对话时，仍需说明今天允许执行的操作。卡片不保证历史任务已实际完成。

## 存储、备份与卸载

默认 Windows 数据在 `%LOCALAPPDATA%\RelayDesk`，Linux 在 `~/.local/share/RelayDesk`。自定义路径要在每条命令前加同一个 `--data-dir`，且放在源码目录外。

```console
python -m relaydesk --data-dir "D:\我的接力台数据" serve
python -m relaydesk --data-dir "D:\我的接力台数据" backup "D:\备份\接力台-01.sqlite"
```

备份包含私人消息和文件路径，未加密，不要上传 GitHub。恢复时关闭应用，把备份复制到一个空数据目录并命名为 `index.sqlite`，运行 `doctor` 检查后启动。不要覆盖唯一备份。

卸载只需关闭终端并移除源码目录。数据目录独立保留；确认不再需要时再自行删除。程序不安装服务，不设置计划任务，不更改现有项目。

## 当前边界

本工具能组织来源、状态和成果，不能自动判断全文覆盖、保证复习成绩、修复游戏、验证论文或让关闭的 Codex 自行运行。中文关键词检索不是语义检索。手工笔记、验收状态和版本关系需要使用者核对。

本地网页也需要临时凭据，不要分享启动地址或把端口开放到公网。自动遮盖不代表完全脱敏。Windows 没有硬内存配额；没有多用户隔离或同账号恶意进程防护。
